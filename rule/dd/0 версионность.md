# Версионность проекта

Формат версии:

`0.MINOR.PATCH`

## Правила

- Первая цифра остаётся `0`, пока явно не принято решение перейти на `1.x`.
- `MINOR` — счётчик активных дней разработки.
- `PATCH` — счётчик пользовательских задач в пределах одного дня разработки.

### Новый день разработки

При первом изменении репозитория в новый календарный день:

- увеличить `MINOR` на `1`;
- сбросить `PATCH` в `1`.

Пример:

`0.5.6` → `0.6.1`

### Следующая задача в тот же день

Каждый следующий пользовательский набор изменений в тот же день увеличивает только `PATCH`.

Пример:

`0.6.1` → `0.6.2` → `0.6.3`

## Что считается одной версией

Один пользовательский запрос = один PATCH.

Неважно, если для его выполнения пришлось:

- изменить несколько файлов;
- сделать несколько коммитов;
- исправить несколько связанных частей;
- добавить код, стили и документацию.

Это всё считается одним набором изменений.

## Когда версия не меняется

Версия не увеличивается при:

- обсуждении;
- анализе;
- просмотре кода;
- диагностике;
- исследовании;
- ответе на вопрос;
- проверке состояния проекта,

если файлы репозитория фактически не изменялись.

## Дата

Для определения нового дня использовать локальную календарную дату проекта/пользователя, а не UTC.

## VERSION.json

В корне проекта хранить:

```json
{
  "version": "0.6.1",
  "lastChangeDate": "2026-08-25"
}
```

При каждом изменении версии обновлять:

- `version`;
- `lastChangeDate`.

## Отображаемая версия

Если версия выводится в:

- интерфейсе;
- API;
- CLI;
- логах;
- HTML;
- других публичных местах,

она должна обновляться одновременно с `VERSION.json`.

## Пример

```text
0.1.1 — первая задача в первый день разработки
0.1.2 — вторая задача в этот же день
0.1.3 — третья задача в этот же день

0.2.1 — первая задача на следующий день
0.2.2 — вторая задача этого дня

0.3.1 — первая задача ещё через один активный день
```
