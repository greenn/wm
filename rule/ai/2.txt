# Раздел 2 — каноническая карта устройства WM

## Назначение

Этот раздел является заданием для будущего Codex на сборку `AGENTS.md` и структурированной документации `aidocs` по WM. Документация должна описывать фактический код, помогать выполнять изменения и явно отделять текущий канон от legacy.

## Приоритет источников

1. Последние явные решения владельца.
2. Фактический код текущей ветки v2.
3. Канонические документы `rule/ai`.
4. Материалы `rule/dd` как концептуальный источник.
5. Старые проекты и старый `man` только как историческая подсказка.

Если код расходится с решением владельца, нельзя молча объявлять одну сторону правильной. В `aidocs` надо зафиксировать целевой канон, текущее расхождение, путь проверки и минимальное исправление.

## Зафиксированный канон

- Целевая серверная среда — PHP 7.2 с обязательным `short_open_tag=On`; в проектном коде используются короткие PHP-теги.
- Новый фронтенд — Vue 3. Vue 2 является legacy.
- `r` — resource layer, а не отдельный Resource Manager.
- `rb`, `lay`, `site`, `admin`, `gss3` и другие имена обозначают самостоятельные именованные RM. Их физическое положение определяет manager и не обязано быть одним и тем же для всех RM.
- Директория становится компонентом RM только при наличии точного entry-файла `<component>.class.inc`. Вложенные шаблонные, data-, support- и служебные директории без такого entry не являются компонентами сами по себе.
- IQ connector, library connector и RM component connector — разные механизмы.
- `rb` — обязательный базовый RM. `lay` не является обязательным для любой страницы, но входит в канонический комплект нового проекта, пока аудит зависимостей не доказал обратное.
- `site` — базовый RM сайта; прикладной проект использует собственный RM, например `gss3`.
- Канонические страницы — v2. Старые page-системы документируются только в legacy-разделе.
- PHP-router выбирает серверную страницу и оболочку. `vue-router` допустим внутри приложения, каталога или корзины, но серверная точка входа, прямые URL, reload и fallback должны сохраняться.
- Каноническая админская точка входа — `/admin/index.php`.
- Root API сначала ищет `<route>.<method>.inc`, затем `<route>.inc`.
- `wd` используется для частого визуального сравнения реализации с эталонными изображениями.
- `mqr` — необязательный runtime JS scaler; это не замена CSS media queries.
- URL-version хранится под `site/uv`; `qv()` добавляет cache-busting версию.
- `wb` пока является зарезервированным будущим WebBuilder. Нельзя выводить его API из старых `w()`, `wb()` или похожей морфологии.
- Данные могут поступать из PHP, текстовых файлов, JSON, БД и других существующих источников. Формат нельзя унифицировать без задачи.

## Обязательная карта `aidocs`

Будущий Codex должен отразить как минимум темы из файлов `2 resource-layer.md` — `2 wb.md`, а также:

- bootstrap и оба режима подключения `web`;
- IQ сайта и проекта;
- каждый именованный RM, его компоненты, connector, шаблоны, CSS/JS/Vue/API/data;
- страницы, server router, `.htaccess` и API router;
- PHP-функции вместе с локальными подфункциями;
- assets, fonts, images, `wd`, `mqr`, `uv`;
- отдельные текущие, legacy и unresolved-разделы.

## Рабочий алгоритм

1. Определить `DOCUMENT_ROOT`, реальный bootstrap и активные IQ connectors.
2. Определить текущие `iqSite`, `iqPro`, `rMain`, pages env и пути RM.
3. Для каждого RM найти manager, его `rDir()`, helper-ы и только затем компоненты.
4. Считать компонентами только директории с `<component>.class.inc`.
5. Для каждого компонента построить связи: connector → class → методы → templates/calls → CSS/JS/Vue → API/data → страницы-потребители.
6. Проверить маршруты от HTTP URL до конечного PHP/template/API-файла.
7. Зафиксировать точные пути и символы; не угадывать отсутствующее API.
8. Проверить PHP 7.2 и `short_open_tag=On`; Vue-код проверять как Vue 3.
9. JSON по умолчанию учитывать по путям и количеству. Содержимое больших продуктовых JSON не читать без отдельной необходимости и разрешения.
10. Legacy не переименовывать, не переносить и не исправлять попутно.

## Критерий готовности

Раздел готов, когда другой Codex может по `AGENTS.md` и `aidocs`:

- найти точную точку подключения сайта, проекта, библиотеки и RM-компонента;
- добавить страницу, component/template, PHP-функцию или API route в существующем стиле;
- объяснить server routing и границу с Vue routing;
- проверить assets/cache busting и выполнить визуальную сверку через `wd`;
- отличить current v2, проектную реализацию, legacy и ещё не реализованный замысел;
- не обращаться к физическому пути ресурса там, где предусмотрен RM.
