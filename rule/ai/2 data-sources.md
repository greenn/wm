# Источники данных

WM не навязывает единый storage. По задаче данные могут поступать из PHP include,
текстового файла, JSON, базы данных, API или другого уже поддержанного источника.

Выбор определяется:

- владельцем данных и местом в архитектуре;
- объёмом и частотой изменения;
- требованиями к выборке/транзакциям;
- правами доступа и чувствительностью;
- существующим contract конкретного RM.

Нельзя переносить всё в БД/JSON только ради единообразия. Site RM может работать
с БД напрямую либо обращаться к внутреннему admin API, если это даёт более ясную
границу.

Безопасность исследования:

- продуктовые/каталожные JSON в dot-projects не читать массово;
- сначала достаточно paths, counts и schema-level сведений;
- credentials/settings не копировать;
- user input валидировать, output кодировать по контексту;
- writes выполнять атомарно и с понятным recovery;
- тесты не изменяют production data.
