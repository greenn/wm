# Предложения sug

sug хранит необязательные улучшения, которые выходят за пределы текущего задания. Предложение не является разрешением на реализацию.

## Процесс

1. Создать следующий свободный последовательный номер.
2. Описать проблему, доказательство, ожидаемый эффект, риски и минимальный вариант изменения.
3. При необходимости добавить короткий code block или diff-пример, не меняя рабочий код.
4. Сообщить владельцу о предложении после завершения основной задачи.
5. Дождаться явного решения: одобрить, изменить, отложить или отклонить.
6. Реализовывать только одобренное предложение отдельным контролируемым изменением.

Рекомендуемое имя: 0001-краткое-название.md. Место хранения: man/sug. Нумерация не переиспользуется. Изменения .htaccess, глобального router и общих contracts всегда проходят этот процесс, если не были прямо включены владельцем в задачу.
