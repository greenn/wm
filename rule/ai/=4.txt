Этап 4 — тестовый ресурсный модуль blank/rm

Цель

Создать минимальный тестовый ресурсный модуль `blank/rm` и получить доступную
страницу `blank/rm/index.php`, подтверждающую, что правила RM, IQ, templates и
assets поняты правильно.

Перед началом

1. Завершить `AGENTS.md` и необходимые разделы `aidocs`.
2. Проверить канонические v2-вызовы по `.vmk4`, `.blank`, `r/rb`, `r/lay` и
   текущему RM loader.
3. Не копировать legacy-реализацию, если она расходится с v2.

Требования

- RM может размещаться в выбранном для blank месте, но его тип и entry point
  должны быть зарегистрированы существующим механизмом framework;
- каждый настоящий компонент имеет обязательный `<component>.class.inc`;
- минимум один template вызывается через RM API, без ручной сборки физического
  пути из страницы;
- CSS и JS подключаются существующим source/resource механизмом;
- PHP совместим с 7.2 и использует только короткие теги;
- JavaScript не требует build pipeline; новый Vue-код, если он действительно
  нужен, использует Vue 3;
- диагностические этапы и ошибки выводятся в `console.log`;
- тестовый код размещается в целевой blank-заготовке только потому, что сам этап
  проверяет эту заготовку; прочие тесты по умолчанию относятся к `test`.

Проверка

- `blank/rm/index.php` открывается без fatal error;
- RM connector загружается;
- template и assets разрешаются ожидаемыми путями;
- отсутствующий ресурс выдаёт понятную диагностическую ошибку;
- результат визуально и технически задокументирован в `man` и `aidocs`.
