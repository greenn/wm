WM — журнал заданий и результатов

Назначение

Журнал сохраняет исходный пользовательский запрос, нормализованное задание для
Codex и краткий итог выполнения. `man/log` можно вести уже сейчас.

Файлы

Для каждого задания назначаются локальный год, дата, порядковый номер в пределах
дня и короткий kebab-case title.

Исходный запрос:

```text
man/<YYYY>/<MM-DD> - <N>-<short-title>.txt
```

Расширенное нормализованное задание:

```text
man/log/<YYYY>/<MM-DD> - <N>-<short-title>.md
```

Краткий результат:

```text
man/log/<YYYY>/<MM-DD> - <N>-<short-title>=.md
```

Если фактическая структура `man/log` при создании Documentation Site будет
уточнена, миграция выполняется отдельной согласованной задачей; старые записи не
переименовываются массово.

Содержимое расширенного задания

- цель и границы;
- обязательные решения владельца;
- разрешённые и запрещённые области;
- план атомарных подзадач;
- критерии готовности и проверки;
- ожидаемое влияние на version/Git/docs.

Содержимое результата

- что реально изменено;
- какие проверки реально выполнены;
- новая версия и commits;
- известные ограничения;
- ссылки на предложения в `man/sug`, если они появились.

Безопасность

Не переносить в журнал secrets, credentials, содержимое закрытых файлов,
персональные данные или большие data dumps. Секретные значения заменять описанием
типа данных и безопасной маской.

Когда запись не нужна

Простой анализ или вопрос без repository changes не требует версии и commit.
Создание отдельной log-записи для такого обращения выполняется только если этого
просит владелец или действующий workflow проекта.
