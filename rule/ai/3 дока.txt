# Документация проекта и фреймворка

Документация делится по аудитории:

- 3 man.md задаёт структуру материалов для человека;
- 3 aidocs.md задаёт структуру точных инструкций для агента;
- 4 дока.txt описывает место исторической документации;
- 3 sug.txt задаёт процесс предложений.

## Что документировать

Для каждой страницы фиксируются URI, PHP-router, подключённые RM, компоненты, шаблоны, client-side routing и ожидаемый результат. Для каждого RM фиксируются публичный API, зависимости, компоненты и порядок инициализации. Изменения страниц и модулей сопровождаются краткой историей изменений.

## Приоритет источников

1. Прямое подтверждение владельца.
2. Текущий контракт v2 и проверенный код WM.
3. Документация rule/ai.
4. Бланки и действующие примеры.
5. Legacy-проекты и старая документация — только справка.

Документация не должна раскрывать credentials, копировать excluded settings или пересказывать продуктовые JSON.
