Этап 3 — автономный Documentation Site в man

Цель

Создать внутри `man` независимую от runtime WM Developer Documentation Site,
которая открывается на используемом PHP-сервере и хранит содержимое в
структурированных Markdown-файлах.

Аудитория и границы

- `man/wm` — основная human-документация по framework;
- `man/site` — страницы и устройство текущего сайта;
- `man/admin`, `man/admin2` или `man/kot` — документация соответствующей
  админки;
- `man/rm/<rm-name>` — компоненты именованного RM, API, templates и assets;
- `man/sug` — предложения со сквозной нумерацией и статусом approval;
- `man/log` — журнал заданий и изменений;
- `aidocs` не дублируется целиком: это отдельная agent-first карта.

Требования к UI

Референс: `rule/ai/4 man-ui.png`.

- постоянная левая навигация по разделам;
- центральная колонка с текстом документа;
- правая область для примеров, code blocks и связанных пояснений там, где она
  действительно полезна;
- цветовые notice-блоки и плавающие элементы только по смыслу;
- подсветка синтаксиса code blocks;
- адаптивность без потери навигации и читаемости;
- логотип имеет `cursor: pointer` и ведёт на титульную страницу;
- интерактивные элементы имеют понятные `title`/tooltips;
- успешные загрузки и ошибки подробно отражаются в `console.log`.

Технические требования

- реализация находится только внутри `man`;
- контент хранится в Markdown и тематических подпапках;
- сайт не зависит от IQ, RM или project runtime WM;
- не вводить обязательный Node/build pipeline;
- новые зависимости использовать только после обоснования и approval;
- путь к документу и ошибки чтения должны быть безопасно обработаны;
- контентные файлы не должны позволять произвольное чтение за пределами `man`.

Содержательные требования

- страницы показывают, из каких RM/components/templates они собраны;
- RM-документы перечисляют компоненты, обязательные connectors, API, templates,
  CSS/JS и изображения;
- журнал доступен как по страницам, так и по модулям;
- технические утверждения опираются на `rule/ai` и проверенный код v2;
- legacy явно помечается и не выдаётся за рекомендуемый способ разработки.
