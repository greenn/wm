WM — exclusions, закрытые данные и секреты

Обязательные закрытые области

- `rule/dd/-` — не читать, не искать внутри, не изменять и не использовать как
  источник.
- `rule/ai-` — не читать, не искать внутри, не изменять и не использовать как
  источник.

Project overlays

- Dot-проекты вроде `.vmk4`, `.ash`, `.gss1`, `.ripr`, `.kp`, `.kp2`,
  `.zo`, `.tosno`
  разрешено исследовать, когда они нужны текущей задаче.
- Эти project directories не включаются в Git WM.
- `.blank` и производные вроде `.blank2` являются исключением: это поддерживаемые
  заготовки, их разрешено изменять и коммитить по задаче.
- Не выполнять массовый обход всех dot-проектов, если достаточно current v2 и
  одного целевого примера.

JSON и большие данные

- Не читать массово продуктовые, каталожные и контентные `*.json` в legacy и
  project directories.
- При поиске файлов и текста по таким деревьям добавлять явное исключение JSON.
- Точный metadata JSON можно читать только когда он прямо нужен поставленной
  задаче и не содержит секретов; общее разрешение на исследование проекта не
  означает разрешение выгружать все JSON.
- Не помещать содержимое больших data files в вывод инструмента, documentation
  или prompt.

Секреты

Не читать и не раскрывать без прямой необходимости:

- `.env` и локальные environment configs;
- API keys, access/refresh tokens, cookies и sessions;
- пароли, private keys, certificates и credentials;
- database dumps, резервные копии и пользовательские персональные данные.

Если задача требует работы с секретом:

1. использовать только минимально необходимую часть;
2. не печатать значение в commentary, console output, docs или commit;
3. маскировать диагностические сообщения;
4. не переносить secret в новый файл;
5. при необходимости нового доступа запросить владельца, а не угадывать.

Git exclusions

- Перед commit проверять состав staged files.
- Не добавлять закрытые области, project overlays, secrets, dumps, generated
  caches и несвязанные пользовательские файлы.
- Не изменять `.gitignore` только потому, что найден untracked-файл; сначала
  установить его назначение и действующее решение владельца.

Поддержка списка

При появлении новой закрытой директории или типа данных обновить этот документ и
соответствующий технический exclude-механизм. Добавление exclusion не разрешает
удалять уже существующие файлы.
