Этап 1 — подготовка rule/ai

Цель

Преобразовать концептуальные материалы из разрешённой части `rule/dd` в полный,
непротиворечивый и пригодный для будущего Codex набор документов `rule/ai`.

Источники

- корневые файлы `rule/dd`, кроме исключённого подкаталога `rule/dd/-`;
- явные ответы владельца;
- текущая реализация WM, включая `web`, `r`, `api`, `admin`, `kot`, `fonts`,
  `css`, `js`, `.vmk4`, `.blank` и `.blank2`, когда это необходимо для проверки
  фактов;
- legacy-проекты только как справочный материал и без чтения продуктовых JSON;
- старый `man` только для поиска названий тем, а не как каноническая истина.

Требования к результату

1. Сохранить полезный смысл каждого разрешённого исходного файла.
2. Исправить опечатки, разорванные ссылки, двусмысленные формулировки и неверные
   предположения о текущем коде.
3. Встроить решения владельца непосредственно в соответствующие документы.
4. Не удалять полезные повторы: дубли допустимы, если документ остаётся
   самостоятельным и удобным для последующей обработки.
5. Добавить отсутствующие тематические документы, в частности по IQ, resource
   layer, RM connectors, `lib`, pages/router, API router, assets, `wd`, `mqr`,
   `uv` и будущему WebBuilder.
6. Явно различать будущий WebBuilder и существующую PHP-функцию `wb()` — word
   bank для морфологии.
7. В каждом техническом документе отделять подтверждённый текущий API от планов,
   legacy и предположений.
8. Соблюдать exclusions и не переносить в `rule/ai` секреты или содержимое
   продуктовых JSON.

Готовность этапа

- `0 rule.txt` даёт полное оглавление;
- `0 owner-decisions.md` фиксирует обязательные решения;
- документы не противоречат PHP 7.2, short tags, v2 и Vue 3;
- все ссылки указывают на существующие или явно запланированные файлы;
- будущий Codex может приступить к этапу 2 без повторного чтения черновиков.
