# Предложения по развитию

`man/sug` хранит идеи вне текущего задания. Предложение не является
разрешением на реализацию.

## Именование

```text
0001-краткое-название.md
0002-следующее-предложение.md
```

Номер сквозной, не переиспользуется и не зависит от статуса. В карточке
указывают проблему, доказательство, ожидаемый эффект, риски, минимальный
вариант и status approval.

## Процесс

1. Выбрать следующий свободный номер.
2. Описать проблему без изменения runtime.
3. Сообщить владельцу о proposal.
4. Получить решение: approve, revise, defer или reject.
5. Реализовать approved proposal отдельным контролируемым изменением.
6. Связать commit и журнал с исходным номером.

Изменение global `.htaccess`, router или общего contract проходит этот процесс,
если оно не было прямо включено владельцем в текущую задачу.

На момент создания Documentation Site активных нумерованных proposals внутри
`man/sug` нет.
