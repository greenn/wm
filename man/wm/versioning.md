# Версия и Git

Источник текущей версии WM — `VERSION.json`. Номер не нужно вручную размножать
по страницам документации. Версия `web` хранится отдельно в `web/web.php`.

## Атомарный PATCH

Один самостоятельно объяснимый commit повышает PATCH на один. Количество
файлов внутри него не влияет на число версий. Read-only анализ без repository
changes версию не меняет.

```text
20.0.2 -> 20.0.3 -> 20.0.4
```

Перед commit:

1. прочитать текущий `VERSION.json`;
2. обновить PATCH и локальную дату `Europe/Moscow`;
3. синхронизировать отображаемую версию;
4. проверить scoped diff и отсутствие чужих изменений;
5. выполнить относящиеся проверки;
6. записать краткий результат в журнал.

## Default workflow

Если владелец не задал иное, проверенный атомарный commit отправляется прямо в
`main`. PR используется только по прямому указанию. Force/history rewrite не
являются частью обычной работы.

Dot-project overlays служат примерами и не коммитятся. `.blank` и `.blank2` —
отдельные коммитируемые templates, но их runtime нужно проверять до копирования.
